Ringkasan eksekutif

OmniMFT Ops Copilot adalah AI agent yang membantu tim operasional MFT melacak transfer file, mendiagnosis kegagalan, menjaga masa berlaku sertifikat, memproses ulang file, dan meng-onboard partner SFTP baru — cukup lewat percakapan.

Agent tersedia di dua tempat: di Boomi Agentstudio (cloud, untuk pengguna bisnis) dan sebagai agent lokal di Claude Code (untuk engineer). Keduanya memakai logika OmniMFT yang sama dan sudah diuji terhadap SecureTransport 5.5 di lab.

File yang diunggah partner ke SecureTransport otomatis diteruskan ke Boomi, divalidasi, diaudit, dan dibalas dengan tanda terima. Seluruh integrasi berjalan tanpa membuka port masuk ke jaringan on-premise.

Empat kapabilitas inti

Pelacakan & diagnosis

Menjawab pertanyaan status transfer dalam bahasa natural: pengirim → penerima, protokol, status, ukuran, waktu. Transfer gagal disertai pesan error ST dan diagnosis penyebab.

Penjaga sertifikat & key

Mengaudit sertifikat SSL/TLS, SSH key, dan PGP key di ST. Yang sudah kedaluwarsa ditandai CRITICAL, yang habis dalam 30 hari WARNING, lengkap dengan saran perintah perbaikan.

Orkestrasi & reprocess

Mengorelasikan transfer ST dengan eksekusi Boomi, menampilkan alasan penolakan Boomi, dan me-resubmit transfer agar ST mengirim ulang file ke Boomi.

Onboarding partner

Membuat partner SFTP baru yang langsung ter-rute ke Boomi: akun, transfer site Generic-HTTP(S), dan subscription — dengan dry-run, persetujuan, dan rollback otomatis.

Arsitektur solusi

Alur file: Partner → SecureTransport → Boomi

  • File kosong ditolak Boomi (ST_INBOUND_REJECTED) sehingga transfer di ST tercatat Failed dan bisa didiagnosis agent.
  • ST otomatis mencoba ulang push yang gagal; agent mengenali error berulang sebagai retry, bukan insiden baru.

Agentstudio ↔ on-premise: outbound-only bridge

  • Laptop/host on-prem menjalankan bridge worker yang hanya membuat koneksi KELUAR (HTTPS) ke Boomi Cloud — jalur yang sama dengan yang dipakai Boomi Atom.
  • Snapshot data ST (transfer, sertifikat, riwayat Boomi, health) diterbitkan setiap ±1 menit ke penyimpanan di Boomi Cloud.
  • Aksi dari Agentstudio (onboarding, resubmit, pencarian live, refresh) masuk antrean di Boomi; bridge worker mengambil, mengeksekusi ke ST, lalu menerbitkan hasilnya.
  • SecureTransport tetap privat di balik VPN; kredensial admin ST tidak pernah meninggalkan host on-prem.

Mengapa outbound-only? Laptop korporat memakai Zscaler (inspeksi TLS, memblokir aplikasi tunnel) dan ST hanya terjangkau via FortiClient VPN. Pola outbound-only patuh kebijakan keamanan tanpa pengecualian khusus.

Agent lokal (Claude Code)

Untuk engineer, logika yang sama tersedia sebagai MCP server lokal di Claude Code yang mengakses SecureTransport langsung lewat VPN.

Keamanan & kepatuhan

Tanpa port masuk

Tidak ada tunnel atau port yang dibuka; semua koneksi keluar via HTTPS ke *.boomi.com, patuh Zscaler.

Kredensial tetap on-prem

Kredensial ST dan Boomi disimpan di .env (mode 600). Password partner baru disimpan di secrets/ dan tidak pernah ditampilkan.

Persetujuan manusia

Resubmit dan eksekusi onboarding wajib persetujuan di Agentstudio; onboarding selalu didahului dry-run.

Aksi ter-allow-list

Bridge hanya menjalankan aksi yang diizinkan; endpoint tujuan Boomi dikunci di sisi on-prem, tidak bisa diubah dari chat.

Guardrail agent

Menolak permintaan kredensial, operasi destruktif, dan konten private key; isi tool result diperlakukan sebagai data.

Jejak audit

Setiap permintaan dan file masuk tercatat di log eksekusi Boomi (OMNIMFT_REQUEST, ST_INBOUND).

Panduan demo

Runbook

  1. Sambungkan FortiClient VPN (ST 192.168.0.21 harus terjangkau).
  2. Jalankan bridge: ./start-bridge.sh lalu cek ./start-bridge.sh --status (harus RUNNING).
  3. Buka Boomi Agentstudio → OmniMFT Ops Copilot → mulai percakapan.
  4. Jalankan skenario demo (lihat bagian berikut).
  5. Setelah selesai: ./start-bridge.sh --stop.

Skenario yang disarankan

“Transfer apa yang gagal 7 hari terakhir dan kenapa?”
Agent membaca snapshot, menjelaskan tiap kegagalan beserta penyebab dan perbaikannya.

“Cek sertifikat yang expired atau akan expired 30 hari ke depan.”
Daftar CRITICAL lalu WARNING, dengan saran perintah perbaikan.

“Kenapa empty_file.csv dari omnimft_e2e ditolak Boomi?”
Korelasi ST (Failed) dengan Boomi (ST_INBOUND_REJECTED, 0 byte) + retry otomatis ST.

“Onboard partner SFTP baru PT_Maju_Logistik dan route ke Boomi.”
Dry-run → persetujuan → eksekusi → detail koneksi SFTP (±30–60 detik).

Keterbatasan & langkah berikutnya

Keterbatasan

  • Snapshot tertinggal ±1–2 menit; untuk data detik ini gunakan refresh atau pencarian live.
  • Aksi lewat antrean butuh ±10–30 detik termasuk polling hasil oleh agent.
  • Host bridge dan VPN harus aktif saat demo; jika mati, agent melaporkan bridge offline.
  • Tracking ID ST tidak ikut terkirim ke Boomi (keterbatasan plugin); korelasi memakai nama file, akun, dan waktu.
  • File antrean/hasil di Boomi tidak dihapus otomatis (desain tanpa DELETE); pembersihan bisa dijadwalkan.

Langkah berikutnya

  1. Pindahkan bridge worker dari laptop ke server/VM di lab agar berjalan 24/7.
  2. Ganti akun admin ST bawaan dengan akun API khusus berhak terbatas.
  3. Tambahkan routing lanjutan di Boomi setelah audit (database, API tujuan, atau SFTP lain).
  4. Perpanjang/ganti sertifikat yang expired dan yang akan habis dalam 14 hari.
  5. Jadwalkan pembersihan berkala dokumen antrean di Boomi Cloud.
